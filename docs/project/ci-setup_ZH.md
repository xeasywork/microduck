# CI 配置

> 对应英文原文：[`ci-setup.md`](ci-setup.md)

## 决定：两类密钥、两种触发

正式发布和开发构建使用不同私钥与信任范围。开发密钥允许团队快速验证分支，正式密钥用于用户可安装发布。

当前发布环境没有强制人工审批门，这是明确接受的阶段性风险，而不是被误认为已经受保护。仓库进入真实交付阶段时应重新评估 required reviewers 和分支保护。

## 分级控制损害

- 开发密钥只被开发板信任；
- 正式私钥只进入受保护 CI 环境；
- 公钥随发布或部署文件分发；
- token、私钥和临时制品不打印到日志。

## Secrets、Variables 和环境

CI 中区分真正秘密与普通配置。版本、通道和公开仓库信息可用 variables；签名私钥和访问 token 使用 secrets。`release` environment 是正式密钥的作用域。

## 密钥处理和发布

工作流只在签名步骤解密或读取私钥，生成 manifest 签名后清理临时材料。发布流程构建、测试、打包、签名、上传并记录 provenance。

## 轮换

先发布包含新公钥的过渡版本，再切换签名私钥；旧公钥在设备覆盖率足够后移除。紧急泄露时应停止发布并明确最低安全版本。
