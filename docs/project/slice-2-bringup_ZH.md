# Slice 2 真机 Bring-up

> 对应英文原文：[`slice-2-bringup.md`](slice-2-bringup.md)

## 状态

Slice 2 把更完整的观测、策略、控制和安全路径带到真机。基础行走和服务通信已工作，但 bring-up 暴露了健康报告不足和运行依赖问题。

## 已验证能力

- `robotd` 读取真实 IMU/关节并运行 61 维策略；
- 策略加载和形状检查；
- API、状态和基础控制；
- 开发推送、服务启动和日志。

## 故障与两个原因

表面症状相同，但包含两个独立原因：一个是运行环境/依赖或路径问题，另一个是健康报告没有把真正失败位置说清楚。前者修复后，后者通过更具体的 health reason 和身份信息改善。

## 测试边界

单测覆盖配置、观测和状态机，不能模拟真实总线、动态库、systemd 权限和硬件时序。真机验证步骤必须检查运行 exe、日志、策略加载、循环频率和实际动作。

## 约定与不做

把真机发现转化为可自动化的回归测试；暂不借 bring-up 顺手重构不相关模块，先保证旧能力不回退。
