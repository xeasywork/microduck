# 从手机通过 BLE 更新机器人

> 对应英文原文：[`update-over-ble.md`](update-over-ble.md)

## 已有基础

更新引擎、签名、安装和回滚已经存在；BLE 工作只负责把检查、应用、进度和回滚安全地暴露给手机，不重写更新器。

## 发现并修复的问题

- 长调用会让同一 BLE 会话失去其他响应：改为异步任务和通知；
- 更新进度过于频繁，不适合 20 字节级小管道：合并和限速；
- `update.check` 被引擎锁阻塞：拆开只读检查与事务锁；
- 手机必须能请求回滚，不能只允许向前；
- 客户端超时应是空闲超时，不是整个长任务的总时限；
- daemon 应用后约五秒链路断开是重启路径的一部分，客户端需要重连并继续查询。

手机触发的更新当前在日志中标为 `btd`，更精细的调用者身份仍未完成。通过 BLE 从本地目录安装刻意保持未开放。

## 当前命令面

客户端能检查更新、应用、订阅进度、读取状态和选择/回滚版本。所有操作仍经过更新器签名和健康门。

## 剩余工作和非目标

剩余包括更完整 App 体验、身份、权限和断线恢复。BLE 不承载制品大文件、不开放任意目录安装，也不替代公网下载渠道。
