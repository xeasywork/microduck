# 安装路径曾经没有测试

> 对应英文原文：[`install-path-gap.md`](install-path-gap.md)

## 问题

若干 bug 通过了单元测试和打包测试，却在真实安装路径上失败：文件放错位置、systemd 单元未更新、重启遗漏、release 链接与进程版本不一致。原因是测试验证了各个组件，却没有执行“像设备那样安装并启动”的完整路径。

一个重要后果是：systemd unit 安装在 release 外，可能继续引用已经过时的路径；release 删除不代表由它安装的系统状态消失。

## 为什么旧测试抓不到

- crate 测试不知道 release 布局；
- 打包测试不启动真实 systemd；
- 假服务无法暴露权限、用户和重启时序；
- 开发推送过去没有验证正在运行的 exe。

## 已采取的修复

1. 增加不需要新基础设施的静态一致性测试；
2. 对构建制品运行真实安装流程；
3. `dev-push.sh` 在板上检查服务身份和健康；
4. `scripts/systemd-test.sh` 在容器中运行真实 systemd、安装、切换和回滚；
5. harness 发现的额外路径问题一并修复。

## 版本 skew

开发通道还暴露了协议版本错位：客户端、`robotd` 和 `updaterd` 可能来自不同 revision。健康结果增加明确 revision/API 信息，客户端应拒绝无法安全解释的协议。

## 不做

不把所有测试都变成昂贵系统测试；纯逻辑继续使用快速单测，只有安装、权限、重启和进程身份需要完整 harness。
