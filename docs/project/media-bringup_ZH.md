# 媒体功能真机 Bring-up

> 对应英文原文：[`media-bringup.md`](media-bringup.md)

## 已确认的硬件事实

RK3566 板卡的相机需要正确设备树 overlay；硬件视频编码走 Rockchip MPP，而不是通用 V4L2 编码器。相关设备节点和用户组权限必须正确。

Radxa 软件源提供部分运行库，但所需 GStreamer 插件版本和功能仍有需要自行构建的部分。预编译插件能力不能只凭包名判断，必须在板上检查元素和属性。

## 构建要求

媒体插件固定上游 revision，并安装到 release 或明确系统前缀。arm64 交叉构建必须使用完整、受控 sysroot，避免链接到开发机库。

## 真机测量结论

- `video` 组需要覆盖多个设备节点；
- 在错误位置旋转图像会使帧率从硬件级降到 CPU 瓶颈；
- 3A 引擎必须在流启动前准备好，否则自动曝光/白平衡可能只初始化一次后停留在错误状态；
- 原始画面、检测分支和编码分支需要共享同一采集管线，不能重复打开相机。

## 仍未完成

包括部分相机参数、长期热稳定、更多硬件 revision 验证和若干管线策略。

## 管线决定

不要过早预编码后再尝试从压缩流做感知。更合适的形态是原始相机帧分支给检测与曝光统计，另一支进入硬件编码和 WebRTC。
