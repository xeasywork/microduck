# 宠物行为运行时

`robotd` API v17 改为由机器人上报当前真正能执行的能力，不再让 App 根据产品总清单猜测。
`robot.subscribe` 的返回值新增：

- `runtime`：真鸭 `robotd` 返回 `hardware`，`simulator` 保留给数字孪生；
- `available_behaviors`：当前运行版本及其策略/声音包实际可执行的行为 ID。

App 和 Brain 可以展示友好的产品动作目录，但下发前必须与该运行时能力列表取交集。列表中
不存在的动作就是不可用，不能悄悄模拟成成功。

首批四个小表情使用确定性的站立策略轨迹，不需要单独的 ONNX 文件：`head_tilt`（歪头）、
`curious_scan`（巡视）、`greet`（欢迎）和 `invite_play`（邀请玩耍）。头部与身体指令保持在训练
范围内，并继续经过正常的观测、推理、关节限位和安全链路。安装声音包时，欢迎和邀请会同时
发声；没有声音包时姿态动作仍可执行。

靠近、后退、蹭靠、伸展和兴奋跳等动态宠物动作目前不会出现在真鸭能力列表中。只有对应策略
完成仿真回归并进入机器人发行包后，才允许上报为可用。

`robot.stop`、`robot.enable {on:false}` 和 `robot.relax` 现在都会取消排队及正在执行的临时动作；
人工下发非零移动速度也会打断确定性表情。因此即使 ONNX 动作或宠物表情已经开始，App 的
“先 `robot.stop`、再禁用策略”紧急停止序列仍具有最高控制权。
