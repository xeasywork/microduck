# `robotd` 控制循环设计

> 对应英文原文：[`robotd-design.md`](robotd-design.md)

## 1. 整体形态

`robotd` 独占 Dynamixel 串口，以固定 50 Hz 读取关节和 IMU、构建观测、运行 ONNX、应用安全规则并写回目标。

```text
读传感器 → 更新安全/状态机 → 选择策略 → 构建 61 维观测
→ ONNX 得到 14 动作 → 缩放映射 → 安全裁决 → 写电机 → 发布快照
```

不变量包括：一个总线所有者、一个观测构建器、固定 tick 预算、外围调用不阻塞、错误策略在加载期拒绝。

## 2. 控制路径

`RobotIo` 集中处理舵机发现、同步读写、增益、扭矩、电压和温度。策略驱动必须使用本 tick 的有效传感器，不能伪造“正常观测”。

所有策略共享 `obs[1,61]`，包含陀螺仪、重力、14 关节位置/速度、上一动作和 13 维命令。嘴部不进入运动策略。

策略按翻滚、踢球、捡拾、坐站、站立、行走的优先级选择。技能有时间窗，结束后返回站立/行走；切换时清理历史状态。

安全层监控倾倒、落地、温度、电压、传感器和循环频率。跌倒后先低增益落地、等待稳定，再交给站立策略起身。

## 3. API

请求线程只更新意图快照，控制循环在 tick 边界读取。状态快照包含健康、姿态、活动策略、技能和传感器，读取状态不能阻塞循环。

`enable`、`init`、`relax` 是明确状态机；坐姿开机可使用 sitstand 起身。维护级寄存器操作与普通运动 API 分离。

## 4. 循环周边

手柄只是客户端；里程计复用本 tick 样本；声音、嘴部、theremin、合唱和抚摸事件可挂在循环周围，但不能阻塞它。

## 5～9. 来源、测试和待办

目标是完整替代旧 runtime 且不回退真机能力。测试覆盖控制逻辑、协议、策略形状和安全状态机；硬件验收仍不可替代。完整自主行为大脑仍是延后项。
