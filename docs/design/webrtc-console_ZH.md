# WebRTC 客户端与机器人控制台

> 对应英文原文：[`webrtc-console.md`](webrtc-console.md)

## 0. 原问题

早期测试页要求用户知道端口、URL 和底层 JSON，无法称为控制台。

## 1. `mediad` 提供页面

页面嵌入 `mediad` 二进制，由轻量 HTTP 服务提供。HTTP 和信令虽使用不同端口，但用户只需要一个入口。

## 2. 发现并打开

`duckctl ip` 从已知蓝牙设备获得网络地址，`duckctl open` 在浏览器打开控制台，闭合配网、发现和访问流程。

## 3. 命名

客户端面向“操作一台鸭子”，不应永远以 BLE 传输命名。`duckctl` 可以随着传输演进而保持用户语义稳定。

## 4. 控制台

页面显示视频、状态和有限操作，通过 datachannel 发送统一 JSON-RPC。调试文本框可保留，但日常操作需要明确控件和错误反馈。

## 5. 身份

会话前提供稳定设备名称和 ID，不能依赖会变化的蓝牙地址。

## 6～8. 后续与不做

该页面是遥操作和状态入口，不代表完成公网访问、权限、多用户或 App。当前不引入大型前端框架，不复制 API，也不把页面变成更新器或自主大脑。
