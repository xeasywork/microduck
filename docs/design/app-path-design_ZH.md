# App 路径：`btd` 与 `configd`

> 对应英文原文：[`app-path-design.md`](app-path-design.md)

## 1. 结构

手机经 BLE 进入 `btd`。`btd` 不拥有业务状态，只验证会话并把允许的方法路由给 `configd`、`updaterd` 或 `robotd`。`configd` 是网络和身份的唯一所有者。

## 2. Wi-Fi

板卡统一使用 NetworkManager。配网必须区分密码错误、网络不可达和暂时失败，特别是明确返回 `BadKey`。新增网络包括扫描、写入、激活、确认和持久化。

fake 后端是行为规范，但真 NetworkManager 后端仍需硬件测试。

## 3. GATT 表面

BLE GATT 只是 JSON-RPC 字节管道，不另造 API。安全边界是允许路由的方法子集；高速遥操作、深度流和维护调用被拒绝。

硬件经验包括：订阅和请求连接分工；手机扫描不能只依赖服务过滤；广播频率要足够；慢调用不能饿死其他 lane。

## 4. 授权

systemd 用户/组权限与 BLE 应用授权分开，解析器应位于低权限边界之后。

## 5. 配对和 PIN

底层目前使用 just-works，应用层 PIN 证明物理持有。蓝牙链路加密与应用授权是两件事；当前加密结论仍未完全收敛。

稳定身份不能依赖会变化的蓝牙地址，应使用设备 ID 和名称。

## 6～8. 测试和待办

无无线环境可测试协议、路由、权限和会话；发现、配对、重连、加密和平台差异必须真机验收。主要待办是加密、PIN 重试、手机兼容和地址随机化。
