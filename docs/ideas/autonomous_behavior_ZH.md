# 自主行为栈：待移植能力与想法

> 对应英文原文：[`autonomous_behavior.md`](autonomous_behavior.md)

当前 Rust daemon 中没有旧 runtime 的 `autonomous.rs`，这是项目最大的未移植缺口之一。本文件是规划收集区，不是已完成设计。

## 待移植的旧行为

旧系统包含 16 状态：Chill、LookAround、Wander、TurnInPlace、Zoomies、Startle、Stretch、Ruffle、Preen、Sneeze、Dance、GroundPick、Nap、BallPlay、Petted、Held。

其基础机制包括：

- 能量/心情模型决定状态；
- 新颖度网格记录探索过的位置；
- ToF 避障和数据新鲜度；
- 明暗变化受惊、声音反应和自发声/自运动屏蔽；
- 玩球、睡眠周期和抚摸反应；
- 手柄与自主模式切换及最大自主速度。

环境声音、深度帧、障碍点、声音标签等输入已在当前 daemon 中存在，但尚无统一大脑消费。

## 新增可用输入

- 通过 BLE 稳定 ID 识别附近其他 Microduck；
- 无共享时钟的群体节拍；
- RSSI 粗距离和接近趋势；
- 可扩展广播载荷；
- 实时合成声音；
- ToF 手部距离。

## 行为想法

社交：记住朋友、陌生/熟悉问候、孤独或满足、接近时兴奋、跟随、对同伴动作鼓掌、信息接力和群体投票。

同步动作：随共享节拍点头、摆动、队列和同步舞蹈。

音乐：呼应、轮唱、不同机器人承担节奏/低音/旋律。

## 摄像头检测

摄像头提供精确方向，ToF 提供距离，BLE 提供身份。跟随行为应融合三者，而不是要求单个传感器解决所有问题。视觉工作应位于 `mediad` 或独立感知进程，行为层只消费方位等特征。

## 移植形态

心情、同伴存在和节拍应成为一个统一大脑的输入，不应继续增加彼此独立的临时模式。社交行为默认需要用户同意。推荐第一个行为是“识别并问候”，因为实现成本低且能验证 BLE 发现链路。
